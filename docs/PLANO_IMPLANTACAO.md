# Plano de Implantação — PortfolioHUB

## 1. Objetivo

Organizar o planejamento da implantação do PortfolioHUB, utilizando como base o repositório `Meu-Study-Hub-TI`. O portfólio apresenta conteúdos acadêmicos, disciplinas, projetos e certificados relacionados ao curso de Análise e Desenvolvimento de Sistemas.

## 2. Situação atual

- O portfólio já está publicado no GitHub Pages e, conforme informado, está funcionando.
- O código-fonte está armazenado no repositório `jonathancorreaRS/Meu-Study-Hub-TI`.
- Existe uma estrutura com página principal e pastas para organizar os conteúdos acadêmicos.
- A integração com a API do Google Gemini ainda não foi implementada nem utilizada no site.

## 3. Objetivo desta etapa

Registrar o estado atual do projeto e organizar as próximas atividades do desafio. Este documento é um plano inicial; as etapas devem ser atualizadas conforme forem executadas e verificadas.

## 4. Ferramentas previstas

- **Git e GitHub:** controle de versão e armazenamento do código.
- **GitHub Pages:** publicação do portfólio.
- **Visual Studio Code:** edição dos arquivos.
- **Navegador web:** verificação da publicação, dos links e da apresentação visual.
- **Google Gemini:** ferramenta prevista para a atividade, conforme os requisitos do desafio. Seu uso e eventual integração técnica ainda precisam ser realizados e documentados.

## 5. Plano de atividades

### Etapa 1 — Planejamento

- Confirmar o objetivo e o escopo do PortfolioHUB.
- Registrar o estado atual do portfólio.
- Identificar as atividades necessárias para concluir o desafio.
- Manter evidências das verificações realizadas.

### Etapa 2 — Configuração e GitHub

- Conferir a estrutura do repositório.
- Confirmar a branch utilizada e o estado do repositório.
- Verificar as configurações de publicação do GitHub Pages.
- Registrar as alterações com mensagens de commit claras.

### Etapa 3 — Usuários e segurança

- Revisar quem pode acessar e alterar o repositório.
- Não publicar senhas, tokens ou chaves de API em arquivos públicos.
- Se uma chave Gemini for necessária, seguir o método de armazenamento seguro indicado pelo desafio; não colocá-la diretamente no HTML ou JavaScript público.

### Etapa 4 — Compartilhamento e acesso

- Confirmar que o repositório e o portfólio podem ser acessados pelos avaliadores.
- Documentar como o código é compartilhado.
- Verificar as permissões aplicáveis ao repositório.

### Etapa 5 — Integração e testes

- Executar os testes exigidos no PDF do desafio.
- Verificar links, navegação e visualização em computador e celular.
- Caso seja implementada integração com Gemini, testar respostas, erros e indisponibilidade do serviço.
- Registrar os resultados reais dos testes, sem marcar como concluídos testes que ainda não foram executados.

### Etapa 6 — Revisão e apresentação

- Revisar os arquivos e a documentação.
- Reunir capturas de tela e outras evidências solicitadas.
- Preparar a entrega final e o vídeo de apresentação, respeitando o limite de tempo definido no desafio.

Este documento organiza o planejamento com base no estado do projeto informado pelo estudante. Antes da entrega final, os itens devem ser conferidos com o PDF oficial do desafio para garantir que todos os requisitos, nomes de etapas e evidências correspondam exatamente ao enunciado.
